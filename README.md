# shecan-db-access-framework

A Python 3.12+ FastAPI service scaffold for MongoDB database access.

## Install and run

Install dependencies with [uv](https://docs.astral.sh/uv/):

```sh
uv sync
uv run shecan-db-access-framework
```

The service listens on `http://127.0.0.1:8000`.

- Swagger UI: `http://127.0.0.1:8000/docs`
- ReDoc: `http://127.0.0.1:8000/redoc`
- Health check: `GET http://127.0.0.1:8000/health` returns `{"status":"ok"}`.

For development with automatic reloading:

```sh
uv run uvicorn shecan_db_access_framework.app:app --reload
```

FastAPI provides the HTTP interface, Uvicorn runs the server, and PyMongo provides
MongoDB database handles. Initialize SQLite before starting the server. The
health endpoint checks only that the HTTP service is running.

## Initialize SQLite

Run from the repository root with the SQLite CLI installed:

```sh
sqlite3 dbs.db < init_db.sql
```

The script creates a single table, `dbs`, with an automatically assigned integer
`db_id`, a required website URL (`sheurl`), and a required MongoDB database name
(`dbtoken`). Running it again preserves existing records.

At startup, the server reads all entries into `app.state.dbs`, keyed by `db_id`.
Each entry contains `db_id`, `sheurl`, `dbtoken`, and `database`, a PyMongo database
handle created as `client[dbtoken]`. Startup ensures a unique `asset_name` index
on each database's `assets` collection and a unique `product_name` index on its
`products` collection before accepting requests. All handles
share one client, which closes on shutdown. The cache is cleared on shutdown;
SQLite changes require a restart.

Set `SQLITE_DB_PATH` to override `dbs.db` (relative to the working directory)
and `MONGODB_URI` to override `mongodb://localhost:27017`. Missing SQLite files or
tables and invalid MongoDB database names fail startup. Index creation requires
MongoDB to be reachable and creates missing collections. Existing duplicate
asset or product names or index creation failures prevent startup; no records are removed
automatically.

## Asset API

Assets are stored in the `assets` collection of the MongoDB database selected by
an exact `sheurl` match in the startup cache. Sites sharing a database share its
assets and products. Conflicting database mappings
for the same `sheurl` return 409; unknown sites return 404.

Every asset and product endpoint requires a nonempty `sheurl` query parameter.
POST and PUT bodies contain only document fields; `sheurl` only selects the
database and is not added to stored documents or responses. POST and PUT reject a body `sheurl`
with 422.
Existing stored documents remain valid.

`asset_name` is unique within each database's `assets` collection, including when
multiple sites share a database. The index applies to both inserts and updates.

| Method | Endpoint | Input | Result |
| --- | --- | --- | --- |
| POST | `/assets?sheurl=...` | Query `sheurl`; JSON body | Create an asset; 201 with saved document |
| GET | `/assets?sheurl=...` | Query `sheurl`, optional `skip=0`, `limit=100` (maximum 1000) | List assets |
| GET | `/assets?sheurl=...&asset_name=...` | Query `sheurl` and `asset_name` | Read one asset by name |
| PUT | `/assets?sheurl=...` | Query `sheurl`; JSON body | Create or replace an asset by its body `asset_name`; 200 with saved document |
| DELETE | `/assets?sheurl=...&asset_name=...` | Query `sheurl` and `asset_name` | Delete one asset by name; 204 |

POST and PUT bodies require nonempty string fields `asset_name` and `asset_url`.
Additional JSON fields, including nested objects and arrays, are
preserved without a fixed schema. POST and PUT accept `asset_name` only in the
request body; GET and DELETE accept it only as a query parameter and have no
request body. PUT selects the database using query `sheurl` and the asset using
the body `asset_name`, then replaces all fields except `_id`;
omitted fields are removed. If no asset matches, PUT creates it with a generated
`_id`. PUT does not rename assets. GET and PUT do not accept
an ID in the URL. GET with query `asset_name` returns one document or 404;
omitting it returns the paginated list. DELETE requires query `asset_name`.
`_id` is generated by MongoDB and returned as a string.
Request bodies cannot set `_id` or use top-level names starting
with `$`, and values must be BSON-compatible. Invalid input returns 422, GET and
DELETE of missing assets return 404, duplicate asset names return 409, and other MongoDB operation
failures return 503.

```sh
curl -X POST 'http://127.0.0.1:8000/assets?sheurl=amar.com' \
  -H 'Content-Type: application/json' \
  -d '{"asset_name":"Logo","asset_url":"https://amar.com/logo.png","metadata":{"width":128}}'
```

Read by name:

```sh
curl --get http://127.0.0.1:8000/assets \
  --data-urlencode 'sheurl=amar.com' \
  --data-urlencode 'asset_name=Logo'
```

Create or replace by name (the body selects the asset):

```sh
curl -X PUT 'http://127.0.0.1:8000/assets?sheurl=amar.com' \
  -H 'Content-Type: application/json' \
  -d '{"asset_name":"Logo","asset_url":"https://amar.com/new-logo.png"}'
```

Delete by name:

```sh
curl -X DELETE --get http://127.0.0.1:8000/assets \
  --data-urlencode 'sheurl=amar.com' \
  --data-urlencode 'asset_name=Logo'
```

## Product API

Products are stored in the `products` collection, using the same `sheurl` database
selection as assets. `product_name` is unique within each
database's `products` collection, including across sites sharing that database.
The unique index applies to both inserts and updates.

| Method | Endpoint | Input | Result |
| --- | --- | --- | --- |
| POST | `/products?sheurl=...` | Query `sheurl`; JSON body | Create a product; 201 with saved document |
| GET | `/products?sheurl=...` | Query `sheurl`, optional `skip=0`, `limit=100` (maximum 1000) | List products |
| GET | `/products/{product_id}?sheurl=...` | Query `sheurl` | Read one product |
| PUT | `/products/{product_id}?sheurl=...` | Query `sheurl`; JSON body | Replace an existing product |
| DELETE | `/products/{product_id}?sheurl=...` | Query `sheurl` | Delete one product by ID; 204 |
| DELETE | `/products?sheurl=...&product_name=...` | Query `sheurl` and `product_name` | Delete one product by name; 204 |

POST and PUT require query `sheurl` and three product fields in the body:
`product_name`, `product_description`, and `primary_photo_url`, all nonempty
strings. Additional JSON fields are preserved. PUT replaces all fields except
`_id`; omitted optional fields are removed. MongoDB generates `_id`, returned as
a string to use as `product_id`.

Request bodies cannot set `_id` or use top-level names starting with `$`, and
values must be BSON-compatible. Invalid input returns 422, unknown sites or
missing products return 404, duplicate product names or conflicting database
mappings return 409, and other MongoDB operation failures return 503.

```sh
curl -X POST 'http://127.0.0.1:8000/products?sheurl=amar.com' \
  -H 'Content-Type: application/json' \
  -d '{"product_name":"Mug","product_description":"Ceramic coffee mug","primary_photo_url":"https://amar.com/mug.png"}'
```

`sheurl` selects a database; it is not authentication. The asset and product endpoints do not
implement access control.

Run the tests with:

```sh
uv run python -m unittest discover -s tests
```
